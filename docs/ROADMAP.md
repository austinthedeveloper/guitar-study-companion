# Roadmap

This is **sequence-based**, not date-based. Milestones in [MILESTONES.md](MILESTONES.md) are the source of truth for completion.

| Phase | Milestones | User outcome | Main risk |
|---|---|---|---|
| Foundation | M0 | Reproducible local/dev environment | Build and hosting friction |
| First useful import | M1 | Corrected tab phrase from book image | Tab recognition reliability |
| Understanding | M2 | Chord-tone and phrasing insights | Ambiguous harmonic context |
| Learning | M3 | Personalized, trackable exercises | Generic/unhelpful lesson quality |
| Transfer | M4 | Apply phrase in new keys and variations | Unplayable fingerings or bad harmony |
| Retention | M5 | Personal lick library and hosted private beta | Cost, privacy, complexity |

## North-star test

Can the player import a lick from a guitar book and **use its musical idea in a different improvisation context** within a focused practice session?

## Scope guardrails

**Now:** Uploaded images, short phrases, correction UI, analysis, practice, transposition, personal library.

**Later:** Native camera capture, microphone grading, auto-generated backing tracks, whole-book processing, collaborative sharing, mobile apps, sophisticated engraving.

## Product metrics (qualitative first)

- Recognition correction effort per passage
- Fraction of analyses rated musically useful
- Fraction of exercises completed
- Fraction of users able to demonstrate the idea in another key/progression
- AI cost per processed phrase

## Future decision points

1. After M1: Does tab recognition work well enough, or should the editor/manual entry be prioritized?
2. After M2: Is harmonic context supplied by the user sufficient, or do we need better chord recognition?
3. After M3: Is playback essential to learning, or does the lesson plan itself deliver value?
4. After M4: Do users want more creative variation or better fretboard navigation?
5. After M5: Is the next investment audio feedback, backing tracks, or a more robust import pipeline?
